# Linaje de ZetProG

Axion Protocol surge de las lecciones obtenidas durante el diseño, auditoría y remediación aislada de ZetProG. Mantiene historia propia y no es un fork Git ni una continuación automática de ninguna rama de ZetProG.

## Ideas retenidas

- auditoría independiente;
- trazabilidad y manifests;
- custodia y rollback;
- separación entre decisión y ejecución;
- decisiones humanas explícitas;
- adaptadores por runtime.

## Elementos no heredados automáticamente

- capabilities sin loader o consumidor demostrado;
- perfiles no consumidos;
- candidatos ambiguos;
- memoria dual;
- overlays autodeclarados;
- documentación con autoridad implícita;
- skills sin consumidor;
- evidencia mezclada con runtime;
- scripts o infraestructura no utilizados.

## Cambio de enfoque

El objetivo cambia de un framework amplio a una capa compacta de dirección, supervisión, auditoría y evidencia. Toda posible migración se evalúa individualmente como `ADOPT`, `ADAPT`, `REFERENCE`, `ARCHIVE`, `REJECT` o `DEFER`.

## Estado histórico

ZetProG permanece como antecedente histórico independiente. Sus ramas, cambios locales, evidencias y repositorios forenses no forman parte de este repositorio ni adquieren autoridad sobre Axion Protocol.
